## 制作过程与继续编辑

1. 用Blender 4.5打开当前AS，先核对物种、原网格、UV、材质、固定游戏根和本物种骨架。R3修正了8种四足动物的关节支点、腿部外张和局部权重；继续编辑使用R3配对源。
2. 按指导中的动作表编辑完整动作，保持骨名、层级、固定根和骨段长度。四足动作的弯曲由关节承担；鸟类处理足端接触与毛羽整理；鱼类使用连续体波与缓游／快速游动。起步、收步和循环接缝必须与对应动作配对。
3. 导出成套SK、Skeleton和本物种全部动作。沿现有导出保持厘米制、30/60FPS、固定根和文件名；导出后回读FBX。Blender回读时关闭自动设置的Connected，保持与编辑源相同的支点和合法关节位移。
4. 检查接地、支撑滑移、蒙皮边长、帧间旋转、循环及起停接缝；再用UE原生导入/压缩姿态采样核对。阈值、逐物种测量和剩余差异以R3报告及其JSON为准；黑熊足端分数帧最高4.25°差异另行保留，不宣称全骨逐角一致。
5. 更新源文件指纹与配对清单，再导入游戏的本物种独立Skeleton。更新配置中的真实资产路径，重新构建、运行演示，观察缓步／自然活动／逃离／受击／致命倒地及死亡保持。动作制作检查与游戏运行检查分别留证据。

制作脚本快照保留其制作时路径和任务元数据。复跑制作诊断前需将其中的输入、输出目录映射到当前克隆；新游戏接入脚本已通过`paths.py`解析归档源，无需恢复作者机器的Resource绝对路径。旧R1/R2报告是历史证据，当前配对源与R3报告是继续制作入口。重复备份、试验候选、解码缓存和Blender自动备份留在原始本地目录。

## 克隆、构建与游戏接入

在已有Git LFS、UE 5.8.2和已配置GameFactory的Windows环境中执行：

```powershell
git lfs pull
$env:HEARTHWARD_FACTORY_ROOT = '你的GameFactory-3A目录'
$env:HEARTHWARD_UE_ROOT = '你的UE_5.8目录'
python -X utf8 scripts/animals/verify_delivery.py
python -X utf8 scripts/animals/build_runtime.py
python -X utf8 scripts/animals/launch_demo.py --verify
```

已入库的UE资产可以直接构建和运行，不必重新制作或重新导入。需要重导时，先按[工具快照说明](tooling/GameFactory-3A/README.md)准备配套UE适配器，再运行`import_assets.py`和`prepare_world.py`。重导会写入Content，应在专用分支和无未保存编辑器的情况下执行。脚本生成的路径元数据放在被忽略的`.agent-local/animal-factory-output/`。

普通演示双击`scripts/animals/启动动物实机演示.cmd`。Python默认使用PATH中的`python`，也可设置`HEARTHWARD_PYTHON`为现有解释器。游戏内运行无需Blender或Python。
