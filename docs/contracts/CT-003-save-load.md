# CT-003｜存档、世界与知识恢复

状态：DRAFT / APPROVAL_REQUIRED；版本候选0.1；审批PR／Owner未分配。
来源：GDD v0.3第13章；50点全局池与安全规则已确认，R22部分边界未定。

## 不改变的产品规则

所有新游戏进度共用最多50点；自动档默认10实玩分钟，可设1—60；
只轮换未锁自动档，手动与锁定档不自动覆盖；危险中禁存；双方倒地失败；
死亡回档；新进度没有可用容量时先腾位；不增加第51个隐藏退出档。

## 快照候选字段

`save_schema_version`、`campaign_id`、`save_id`、世界修订、生成构建标识、
各模块快照、知识快照修订、完整性校验。加载中的`timeline_epoch`由恢复协调生成新的运行代次，
不能仅复用旧epoch而使历史请求仍有效；campaign/save身份与运行代次区分。

各模块在同一个逻辑快照边界提交状态；不要先保存库存再异步使用已改变的知识版本。
保存的知识包括原始可恢复事实／交流／约定或可重建索引依据；不能只保存某个本地向量库路径。
是否直接快照索引还是重建由工程决定，但必须恢复到该存档知识边界，而不是重建出最新未来记忆。

## 恢复顺序候选

暂停新的世界写入→废止旧会话／动作代次→读取和验证存档→恢复实体、容器和时间→
恢复任务／旗帜／生产与知识→恢复角色和UI引用→允许新命令。
R01/R02/R03/R04/R05未定规则不由加载过程重新推导；按保存的明确状态恢复。

## 文件安全与兼容

保存写入采用可验证完成标记／原子替换等工程措施，避免半写文件被列为可用回档点。
新旧schema不兼容时明确拒绝、提示或运行经测试迁移，不能静默清空记忆。
迁移不得新增超过50点的隐藏用户档；临时写文件不作为额外可选择节点。

## 必测

空档池、新进度容量不足、全锁定、危险延后保存、保存中断、损坏档、
旧schema、物资与知识同回档、另一进度隔离、撤销未来任务、旧LLM回复到达、
重新加载后既定奖励不重复发放、未来随机结果可变化但已保存事实不变。

## 保留未定

环境伤害、传送时状态与禁存交叉等R22边界。契约实现采用明确测试夹具，
不把某个测试场景中的处理偷偷变成所有环境伤害的正式规则。

## TASK-025 v2 局部增量

v2存档格式显式迁移schema1至2；认知、工作槽位、规则、目标归属量、NPC耐久和执行回执同边界保存。恢复产生新运行epoch，未批准候选不自动执行；旧异步/UI句柄失效。原子结算期间拒绝保存。
