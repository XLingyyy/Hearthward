## 实际请求与返回

- `BeginMedicine`、`Eat`、`BeginRescue`返回bool；`CancelAction`、`GiveUp`执行当前动作变更，`Describe`提供当前状态文字。调用者读取真实库存、距离、生命和权限，无权传入成功结果。
- `ReceiveDamage(Amount, Event, Timeline, Fatal)`核验当前epoch并按事件ID去重；同一伤害不能先使人倒地再当残伤致死。用药／扶起为组件内单一动作，完成后清除动作，重复完成不重复扣费或回血。
- 动作记录当前epoch；读档重新绑定同档预留药量并清除旧救援引用和伤害事件集合。倒地、目标死亡、取消和移动阻止旧动作完成。
- 没有新增通用请求／收据协议或GAS依赖。未配置的环境曲线不产生推测伤害；药物恢复比例与持续时间来自物品目录。

## 提交与取消边界

用药开始仅锁定可用药量；完成重新核验目标状态、权限和物资，原子提交扣药与效果。受伤中断时，损耗和动作中断在同一提交中完成；非受伤中断释放预留。按已批准D2，完整药有两半份，半份保留实际药量、重量和效力；不可退回并未持有的制作材料。该表示需与后续物品实例、堆叠、转移及存档共同评审。

锁定不改变总库存，但不可再次用于并发制作、交易、丢弃、转移或另一用药动作。事务内拒绝保存／恢复与重入世界提交；事件发布在提交后。技术失败无部分扣药，实际中断损失不当作技术失败退还。

救援不预扣药物，开始和完成都校验存活救援者、待救目标、剩余期限、距离、路径与环境；期间中断清零动作进度，不延长目标倒地due。目标或救援者终态优先，5秒回调不能复活已死角色。

## 统一时间与事件顺序

普通模拟A/W共同前进，跳时只前进W。生存消费者先计算饱食归零、到10%生命、严重饥饿due等最近事件，与043生产／刷新共用事件时间。到due则停止剩余跳时，不先跳到终点再补死因；没有消费链时拒绝跳时。

同时间优先顺序由设计D6裁定：连续量截至边界→到期期限／伤害→生死派生→有效动作完成→旅行→安全保存。对同一角色的多个伤害须先按事件ID去重再按确定顺序处理，不能依赖TMap遍历或网络回调先后。暂停所有对应计时；读档直接恢复，不重放从零到保存时刻的事件。

## 实际快照内容

| 内容 | 保存原则 |
|---|---|
| 生命状态 | Alive/Downed/Dead主状态、当前／最大生命、耐力／饱食；保存合法性仍按安全规则，普通新档不得包含Downed／Dead |
| 饥饿 | SevereDue（-1表示未严重饥饿）；解除至10的真实结果；不得读档重新发三日 |
| 短计时 | 用药进度、恢复延迟、持续药剩余A与效力；锁定物资由同档库存重建；救援涉及倒地目标，安全规则拒绝该状态保存 |
| 环境 | 生存结构包含溺水剩余A；安全规则拒绝水中／溺水存档，不保存未定义环境事件队列 |
| 身份／权限 | 稀有物授权随档保存；旧时间线结果被epoch拒绝；瞬时伤害事件集合在恢复时清空 |

存档格式升级须在实现任务中另列明确schema及旧档判定。旧Demo没有严重饥饿期限／倒地状态，不能仅凭Hunger=0推算过去何时进入，也不能将Health=0猜成合法Alive。建议旧安全档保留数值并执行经批准的缺失状态迁移；不能迁移的档给出原因并保留原文件。本单现已获准实施保存迁移，具体schema和旧档判定见下方实际接口；不指定虚假的历史时间。

## 044实施协调记录（2026-09-26）

- 玩家现有Gameplay生命／饱食／耐力字段保持权威；共享Survival组件引用它们，弟弟由同一组件持有数值，避免双写玩家属性。
- 半份药使用同源物品的显式半份ID，沿用整数堆叠、物品目录与重量计算；不添加新配方。库存组件预留一个物品，所有扣除／交换／转移入口尊重预留，受伤交换为半份，半份再次受伤耗尽。
- 生存动作使用A时间与当前时间线；动作结算之前先检查生命和期限。伤害事件ID去重；恢复切换时间线并清除旧动作引用。
- 保存增加版本化的生存快照。旧档无历史期限：保留可迁移的正生命数值，在保存时刻首次建立必要饥饿状态；零生命旧快照拒绝迁移并保留文件。使用显式版本判定，避免缺失字段采用新类默认值。
- 使用现有Actor伤害、移动和导航API；不引入GAS。参考Epic的[Tick依赖说明](https://dev.epicgames.com/documentation/unreal-engine/actor-ticking-in-unreal-engine)，显式安排状态更新与动作完成的次序。

### 实际接口与格式

- `UHearthwardSurvivalComponent`拥有生命状态、药品／救援动作；玩家基础数值仍引用Gameplay，弟弟数值由组件保存。正常运行由WorldClock分两阶段推进：所有兄弟连续量／期限，随后有效动作完成；失败时不再完成动作。
- `FHearthwardSurvivalState::Advance`返回截至致死事件消耗的比例；WorldClock的W跳时入口先预演共同停止边界，再统一推进。完整睡眠与生产／刷新消费者仍属043世界系统后续集成，044未接床跳时。
- 新文件头HWS5、schema5、SurvivalVersion1；保留NPCStateVersion3。未使用独立052分支占用的schema4。旧HWS1/HWS2文件只按明确旧格式迁移，缺失当前生存版本的HWS5被拒绝；不离线推进时间。原文件在成功原子写入前保留。
- `medicine_half`是现有药草膏的半份，重量25（原份50），恢复15%最大生命，不新增配方。持续药读取medicineDuration与healing百分比字段；测试临时配置50%／15秒，不把测试配方写入目录。
- 库存预留数量依旧属于实际库存重量；完成、受伤与进食在状态提交后发布变更事件，Save与Restore在结算期间拒绝重入。
- 坠落通过角色Landed与可配置UCurveFloat，虚空通过FellOutOfWorld；游泳使用CharacterMovement状态，耗耐力参数暂未配置。未配置曲线不推测伤害数值；本单不声称地图已完成所有环境内容。
