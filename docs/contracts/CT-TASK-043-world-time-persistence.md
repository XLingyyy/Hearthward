## 请求、结果与单位

候选操作仅包括普通推进、切昼夜、篝火推进、传送及恢复。入口带 `campaign_id`、当前 `timeline_epoch`、当前世界修订和本次 `operation_id`；复用现有身份与去重方式，字段形态在公共声明任务中统一。

- 普通推进：输入有限非负实玩秒；A与W按1秒＝1游戏分钟推进。
- 切昼夜：输入相反昼夜阶段；不接受伪造的工作量或产出数。只改V并交付已经满足生产条件的批次。
- 篝火：输入已获准范围内的游戏分钟；只推进W，按D1矩阵逐事件处理。缺少必要规则配置返回 `RULE_UNRESOLVED`，不得静默跳过该系统后称整次结算完成。
- 传送：输入已激活目标站点ID，源站由真实位置判断；参与角色／敌人由权威状态取得，模型／UI不提供敌人血量重置列表。
- 恢复：输入已验证快照身份；不通过普通“前进时间”重放到保存日期。

结果至少包含：成功／拒绝／在失败事件点终止、实际到达W、已提交的领域结果摘要、更新后修订和可见失败原因。常见拒绝原因：旧epoch／修订、危险或动作未结束、未解锁站点、落点不可用、规则未定。已成功的同epoch operation_id重试返回原结果，不再次扣料／移动／发奖；不同epoch一律拒绝旧请求。

日与分钟统一使用1440游戏分钟／日。实玩秒不乘60后用于动作；现实系统时钟只作文件日期显示，不能用于世界离线补算。稳定实体ID不能使用临时Actor地址或每次流送生成的新GUID。

## 顺序与跨周期

按D6顺序到达每个事件点。循环跨越周期不能简单“到期次数×产出”，必须在上个事件真实更新后的输入、容量、状态上计算下一个事件。可用解析批量计算优化，但结果必须等价于逐事件；性能上限不能丢弃应有产出或变成隐藏生产封顶。

生产输入、工作进度、输出和完成记录处于同一个逻辑提交边界；旅行所有必随角色和回血集合亦如此。短暂技术失败导致当前原子提交不生效；跳时中的真实生存失败则停在那个时间点，已发生的世界结果保留到回档，不把它当作“跳时请求全回滚且免费恢复”。UI给出实际结果。

同时间共享投入不足时遵循获批的岗位优先序，不能依赖哈希表遍历。事务过程中禁止保存、重入结算或提交模型动作。状态提交后才向UI／伙伴发布事件；伙伴仍受亲见、实际回执及地点知识边界约束，不因收到日历广播获知全部敌情或隐藏奖励。

## 快照最小内容及兼容

| 领域 | 同档持久状态候选 | 恢复后不做的推导 |
|---|---|---|
| 时间 | A、W、V、当前规则版本与周期处理位置 | 不用A反推包含跳时后的W，不按本机时间补生产 |
| 生产 | 批次ID、实际已投入、劳动进度、岗位归属、完成／交付状态 | 不把已有产出重新入库，不无条件退料 |
| 自然点 | 稳定点位ID、剩余量、耗尽时刻、next_due、占地阻塞 | 不把加载日作为耗尽日，不在房内刷新 |
| 敌人与区域 | 身份、生命代次、当前生命／异常／击晕、潜入退出标记、增援终结、控制与胜利 | 不凭当前Actor数重算总驻军，不因流送生成新一波 |
| 生物 | 每株播种／成熟／待收获，每个体成长／繁殖与实际饲料、栏容量状态 | 不用总天数无限复制作物或后代 |
| 奖励／知识／角色 | 复用现有领域状态，加入新领域需要的已领取身份与剩余时间 | 不跨档保留未来奖励、对话、采集或模型动作 |

原有库存、任务奖励和角色字段仍由原模块拥有，上表是需要覆盖的信息，不要求存第二份副本。保存须在单一稳定修订捕获；保存中不得混入后一个修订的知识或库存。

现有 `FHearthwardClockState` 只有ActivePlaySeconds，SaveSubsystem保存为ActiveSeconds。未来分离W/V需要显式schema迁移：对明确没有跳时的旧Demo档可提出 `A=旧值、W=旧值、V=0` 的候选迁移；新敌人／生产数据不能从旧Demo缺省字段推断为“已通关”“已生产”或“未领奖”。旧Demo到正式关卡的映射仍需另行设计，无法迁移时明确提示，不静默清档。本单不改schema或代码。
