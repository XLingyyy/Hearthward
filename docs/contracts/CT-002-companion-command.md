# CT-002｜弟弟委托、执行与结果

状态：DRAFT / APPROVAL_REQUIRED；版本候选0.1；Owner／审批PR未分配。
来源：GDD v0.3第10—11章；Q111、Q247—258；未定R18、R20。

## 产品约束（来自GDD，不是本草案新设）

一个明确目标、最多三步；可以为同一数量目标分多趟完成；受阻返回营地等玩家；
30米内只按距离交流；独立只做安全事务；新对应命令覆盖旧命令；玩家话语不能改客观世界。
三条建议只主动刷新；所有动态回复是文字。更细的覆盖、取消与陈旧建议行为仍要批准。

## 拟议输入／结果边界

`command_id`、`timeline_epoch`、`command_revision`、来源（自由文本／快捷建议）、
玩家原话、目标、至多三步、数量与限制、可知信息的来源修订。
语言解释结果分为：需要澄清、可执行候选、拒绝／不支持；不直接返回“游戏操作已完成”。
接受候选后，由实际执行模块验证权限、对象、距离和资源，再开始动作。

## 候选状态

`NEEDS_CLARIFICATION → ACCEPTED → EXECUTING → COMPLETED`；
不能继续时进入`RETURNING_BLOCKED → WAITING_AT_CAMP`；
覆盖或取消时进入`SUPERSEDED`或`CANCELLED`，它们是工程状态名，不要求照字面展示给玩家。
实际交付量单独累计，0/10、4/10、10/10只能来自真实入库；背包未空不是完成依据。

## 迟到、重复和回档

每个回复和动作关联命令身份、代次与时间线。旧代次结果不得成为新任务的动作；
回档后返回的旧回复不得重新激活未来任务。是否仍向玩家展示迟到文字，由R20决定，
在其决定前仅验证“不能改变新世界”，不自行确定最终UI体验。

模糊目标需确认；资源不足不虚构库存；危险独立任务可拒绝，同行战斗不自动全部拒绝。
跨30米边界、覆盖多条长期规则、失败时的最终提示仍属于R18，须单独说明。

## 评测记录

同一用例分别运行fixture与真实模型；记录模型版本、提示版本、检索版本、实际世界状态、
预期允许结果集合、动作记录和失败原因。措辞不同可接受，虚假完成、越权操作和跨档污染不可接受。
不通过硬编码测试文本伪装成自由语言理解。

## 契约验收

至少覆盖：明确委托、模糊委托、真实缺料、多趟入库、取消、覆盖、受阻返营、
错误玩家陈述、已失效建议、回档后迟到回复、同一操作重复返回。

## TASK-025 v2 局部增量

v2扩展现有CommandTicket身份：规范目标携带能力版本、数量语义、来源、当次约束和接受规则修订；未确认候选不替换执行命令。每个实际效果具有操作标识/载荷与回执，目标归属采集/交付独立于容器总量；明确NPC工作台操作者及物资授权。
