# Hearthward（归火）现状审计与首版缺口

审计日期：2026-09-24  
仓库：`XLingyyy/Hearthward`  
主干快照：`ee3f4c2eede9f856c4589fd4b85b1b05c82a1b6b`  
审计方式：远端只读；设计、任务、配置、关键 C++ 路径与既有验收记录交叉核对。

## 一、结论

Hearthward 已经不是只有对话框的概念演示。它有真实物资结算、伙伴任务执行、知识与世界分离、同时间线存档，以及能安装运行的本地模型 Windows Demo。当前的主要缺口，不是再增加一套 AI 框架，而是让这些能力服务于持续的游戏目标。

目前玩家能够经历的是：**进入自然营地 → 采集或委托弟弟采集 → 入库与取用 → 建工作台、制作、休息或烹饪 → 保存恢复。** 还没有形成首版要求的完整长期循环：**营地发展 → 为一次外出准备 → 探索、潜入、救援或战斗 → 带回人员和资源 → 解锁下一阶段 → 夺回故乡 → 双营地经营。** [S02、S03、S07、S09]

因此，当前可以称为“已发布的小闭环原型，具备值得继续建设的技术底座”，不能称为十小时首版基本完成，也不能仅因很多旧任务标为 Blocked 就反过来说那些系统尚未开发。

本文把“最终完成”的第一交付终点按仓库现行批准范围处理：约十小时首版，夜袭、发展、夺回故乡、第二营地及通关后经营。反击敌方腹地、部族战斗小队、最终投降属于后续扩展方向，不自动加入本轮任务。十小时是内容目标，不是开发工期或已经实测的通关时长。[S03、S06]

## 二、如何判定完成

| 状态 | 本文含义 |
|---|---|
| 已接通的小闭环 | 正常游戏入口能访问，存在实际状态或世界结算，并有相应范围的验证记录；仍可能是 Demo 参数。 |
| 部分实现／开发场景能力 | 有代码、界面或测试，但没有完整接入自然地图，或体验、内容、资产、跨系统验收尚未完成。 |
| 机制已定，尚待施工 | 已有明确玩法条款，但未见相应完整实现。只表示已定部分可按依赖拆建，不代表该模块所有规则都已批准。 |
| 设计尚未闭合 | 关键结算、边界、内容表或体验决定未批准；必须先补设计，不可用原型默认值替代。 |

“设计定案”“代码完成”“主干合入”“Shipping 验证”“Owner 验收”是五件不同的事。每个系统需要分别记录，不能合并成一个完成勾选。

## 三、当前已经做了什么

### 3.1 自然营地真实小循环

| 能力 | 已有内容 | 不应扩大解释为 |
|---|---|---|
| 游戏入口与进度 | Bootstrap 标题页，新游戏进入自然地图营地，继续游戏、手动保存、选节点回档。 | 完整夜袭序章和正式新手流程。 |
| 玩家采集 | 树木、石头、灌木对应木材、石材、草药；5 秒获得 2 份；点位剩余量随档保存；中断和容量限制有结算约束。 | 工具分级、矿业链、所有资源类型、正式再生规则。 |
| 共享仓储 | 背包与真实仓储双向转移，可选择数量，整批校验，保存恢复。 | 两座已可使用的营地；目前主要是单营地入口。 |
| 自由建造 | 工作台、床、篝火的预览、旋转、支撑／坡度／碰撞检查、5 秒施工、取消及打断、扣料和实例恢复。 | 完整房屋模块建造、建筑搬移拆除、设施等级与营地八阶。 |
| 制作维修 | 工作台四种即时配方：箭矢、绳索、石斧、药膏；批量、材料与容量校验；装备维修界面和实际耐久结算。 | 完整武器防具、蓝图、冶炼锻造与正式维修经济。 |
| 休息与烹饪 | 床的短时恢复动作，篝火消耗肉和木材得到烤肉。 | GDD 的昼夜睡眠、可选跳时和跨系统生产结算。 |

当前树／石／草药点容量分别为 12／8／4，尚不自动刷新。床是消耗饱食换恢复的 Demo 行为；肉有初始补给，尚没有完整狩猎供肉链。这说明小循环真实存在，但没有可持续的资源经济。[S02、S17]

### 3.2 AI 伙伴：已经有执行系统，不只是聊天

现有链路为：玩家输入或显式快捷建议 → 本地 Qwen3.5 4B → 结构化候选 → 校验与确认 → UE 执行 → 真实事件、认知和下一轮上下文。模型不直接写库存、坐标、安全真值或伤害。[S02、S10]

| 能力层 | 现有成果 |
|---|---|
| 指令交互 | 自由输入、缺槽澄清、任务卡确认、候选过期／替换、取消与进度、显式刷新建议。 |
| 真实执行 | 采集、多趟返营入库；制作箭矢和绳索；维修自身持有装备；经授权领取缺料。 |
| 移动与行为 | UE 导航、跟随、等待、协助进攻、营地日常；有限重试和回退；携带物资优先保全。 |
| 认知 | 世界真值与 Belief 分离，观察、玩家报告、本人收据分来源；离营后不自动知道实时仓库。 |
| 记忆 | 显式长期记录、编辑和撤销、相关检索；实际行动事件派生 Episode，而非保存一份可漂移的虚构总结。 |
| 主动表达与协作 | 事件触发提醒、队列和冷却、协作习惯提示、Assist／Protect／Regroup 战术策略。 |
| 可靠性 | 上下文分档、真实模板 token 计数、输入预算、迟到回复隔离、存档迁移、无模型时手动任务入口。 |

这些能力并不等于任意自然语言都可靠，也不等于全地图自主生存。当前检索主要是规则／词项与受控记录，不应改称已经完成自动语义记忆。战术能力的部分证据来自开发夹具；自然地图尚无正式敌人，所以不能把它记作完整自然关卡中的战斗协作已交付。[S02、S10]

### 3.3 通用游戏底座

已经有生命、饱食、耐力、负重、装备计重与耐久、经验和技能；22 个物品条目、10 个装备槽、四系 29 个技能节点。九类主要界面以及存档、设置、确认等页面接到了实际系统；任务按真实事件计算进度，奖励同一时间线只领取一次。[S02、S07、S08]

这些成果可复用，但当前“8 个主线步骤＋3 个支线目标”服务于开发场景与早期体验，不是 GDD 的完整“8 主线＋15 支线”。`CampTier`、`maxCampTier=8` 和属性成长公式存在，也不等于营地升级、劳动力与产出系统已经存在。[S05、S07、S08]

### 3.4 资产与发行

已有 4.032 km 边长的 World Partition 自然地图底座、局部营地植被岩石、两名角色的模型骨架材质与基础动作、八类部件组装的营地房屋、家具以及临时显示的石骨斧。地图大，不等于可玩内容密度、路线质量或全图导航已经完成。[S02、S11、S12]

Windows Demo 已完成 Win64 Shipping 打包和本机独立安装，随包提供模型与 CPU／Vulkan 运行库；真实物理输入验证过委托 10 份木材、交付、建工作台、制作箭矢、保存与安装版恢复。发行记录的受测源码是 `8b54550b5f9d7d01c9e9e0f7444826090667f3f5`，不是把所有旧测试重新绑定到本次主干 SHA。[S09]

第二台无开发环境机器、不同显卡与驱动的兼容性仍未验证。中等画质／30 FPS 是已有单机对照结果：较高 GPU 负载会使同机推理超时。它说明性能预算需要认真管理，不证明全硬件达标。[S09]

上述缺口依据现行范围、实现与限制交叉判断，不是逐项“整个模块从零开始”。尤其背包、UI、存档、建造、制作和 AI 不需要推翻重写。[S02、S03、S06、S07、S09、S11、S12]

### 4.1 源码中最值得注意的几个差异

`EnableAdventure()` 在自然图不调用旧地标生成；`CreateLandmarks()` 在自然图直接返回；自然图地点发现和交互还跳过非 camp 条目。因此，“地图／日志页面能打开”“配置有敌人和地点”均不等于正式地图已经有对应内容。[S07、S15]

`UseItem()` 的药品路径目前直接扣 1 件后加生命；现有 `ApplyDamage()` 把穿戴防御汇总处理，尚不是完整按受击部位匹配护甲的正式系统。`Durability` 按物品类型 ID 存储；若正式版允许多件同类装备独立磨损，必须先决定实例语义，再迁移，不能把它当作只改几项数值。[S07]

自然地图已有保存、建造、角色和认知迁移底座，但未来人口、动物、作物、敌人刷新、控制区与双营地也要进入同一时间线。必须随每个功能建设存档与去重，不能在全内容做完之后再“补一个存档任务”。

## 五、设计已经明确，但实现未完成的内容

严格说，尚未完成的大系统多数是“部分规则已定，部分边界待定”，而不是整套设计施工图已经齐全。

| 营地最多八阶，提交材料升级而非营地经验；建筑分别升级。 | 升阶入口、条件检查、建筑等级和效果。 | R11/R13：完整条件表、材料、效果与第二营地差异。 |
| 普通族人初始 20、最多再救 10；同一劳动力池；安全劳动；不因缺粮死亡或罢工。 | 人口、救援入营、分配面板、生活行为、产出。 | R03/R12：一次性投入、岗位与兄弟三工等效、四工维持生活的预算。 |

| 明暗探测、可中断暗杀／击晕、尸体警报传播窗口、分区警戒已有明确基线。 | 整套潜入状态机和场景可读反馈。 | R07/R10/R17：动作衔接、曲线、尸体及具体关卡脚本。 |

| 作物 2/3/4 游戏日成熟；每轮浇水、施肥各一次 +25%，不重复叠加；家畜自动繁殖、成长、满栏停止。 | 作物／动物状态、照料交互、收获、喂养与宰杀。 | R02/R03/R15：跳时、具体物种作物、成本产出与容量。 |
| 钓鱼保留拉扯；失败损失鱼和鱼饵、不扣竿耐久；地图先获得，对应宝箱才生成。 | 输入小游戏、结算、物品链、地图与宝箱持久状态。 | R16：张力、消耗、成功耐久、奖励池和重复奖励。 |

这张表表示“已经知道要遵守什么”，不表示所有项均可立即开整单实现。依赖未决的部分先只做契约和经批准的隔离验证。[S03、S04、S06]

## 六、哪些设计仍然没定

### 6.1 必须优先关掉的五个冲突

| ID | 必须给出的决定 | 不决定的风险 |
|---|---|---|
| R01 | 四日敌人刷新到底作用于谁；与已清敌计数、已控区、永久夺回怎么共存。 | 进度反复清零、死人重复刷经验、胜利失效或关卡卡死。 |
| R02 | 睡眠只切昼夜却结算生产，结算量依据是什么；篝火跳时推进哪些系统。 | 玩家通过睡眠获得无限资源，或不同系统处于不同日期。 |
| R03 | “一次性生产资源”究竟是投入、额度、点位还是产出；耗尽后如何继续。 | 营地生产无法配置可持续且可验收的经济。 |
| R04 | 自然回满血与药品受饱食上限限制如何统一；零饱食与严重饥饿的优先级。 | 战斗难度、治疗价值和死亡规则无法稳定。 |
| R05 | 传送重置哪些敌人的血量与状态；弟弟交战、倒地、普通跟随如何处理。 | 战斗撤离、敌人持久状态、兄弟生死与回档互相矛盾。 |

现在床的短时恢复、资源不刷新等是 Demo 范围，不能当作这些问题的最终答案。[S04、S05、S17]

### 6.2 其余未决设计按工作域整理

| 工作域 | 关联 R 项 | 需要补齐的实际交付物 |
|---|---|---|
| 生存和时钟 | R08/R09/R22 | 药品时长／损耗／移动限制、恢复时钟、严重饥饿、环境伤害、危险状态与存档／暂停表。 |
| 动作、武器和潜入 | R06/R07/R10 | 玩家持盾决策、耐力和再格挡规则、四部位映射、取消窗口、探测曲线、感应能力和尸体边界。 |
| 成长与经济 | R11/R12/R13/R14 | 八阶和六十级全表、技能投入规则、口粮和岗位经济、设施／配方／材料、装备耐久与负重目录。 |
| 动植物与奖励 | R15/R16/R19 | 作物和动物名单、种子／饲料／掉落、繁殖单位、鱼饵与竿耐久、宝藏唯一性、自然刷新／地面物清理。 |
| 关卡和叙事 | R17/R24 | 四区布局、80 人分布和巡逻、8 主线 15 支线逐项任务卡、夺回后支线承接、实际通行参数。 |
| 伙伴完整体验 | R18/R20/R21 | 新活动权限、救助可达性、自动药品与稀有物权限、建议过期反馈、长时间主动交流及知识修正。 |
| 操作、视听与试玩 | R23/R24/R25 | 键位重绑／控制器范围、固定对白清单、舒适性选项、移动环境参数、目标硬件和最终试玩指标。 |

R01—R25 在登记中仍全部 OPEN，但“OPEN”不意味着每条完全没有答案。例如建议失效、认知纠正、显式记忆撤销已经有局部实现；应把这些局部边界登记为已批准增量，再保留真正没解决的部分，不能简单整条关闭。[S02、S04、S10]

此外，部族名称、文化细目、正式服饰和建筑风格、地理原型等仍未定。已生成模型可以是视觉候选，不会自动决定世界观。十五件动物候选资产也不是十五类动物内容表已经批准；占卜仍是候选，不是首版必做模块。[S03、S06、S12]

## 七、必须修正的仓库状态漂移

### 再建设一条完整体验，而不是先填满整张大地图

建议第一新增里程碑是一条由 Owner 批准的约 30—60 分钟体验切片：从正常入口，玩家理解目标；在营地准备并安排一次分工；带弟弟完成一处真实外出遭遇／救援；带回真实成果，改变营地能力；保存退出后能继续。这个长度是切片范围建议，不是开发耗时估计，也不是替代十小时首版。

这一切片要回答：“弟弟为什么值得带上？”“为什么需要资源？”“外出回来后生活发生了什么变化？”先让这三个问题有玩家可感知的答案，再扩四区、更多资源玩法和完整叙事。

最后再进行全系统存档回归、真实表达／任务完成率测试、渲染与模型联合性能、第二机器、十小时全流程与发布候选验收。跨系统保存和基本测试必须随功能一起做，最后阶段只做综合验证，不是首次接入。

对应续号任务与逐项验收见同批文件 `Hearthward_TASK-043-076.md`。全部为 Backlog 草案，没有据此授权实现、付费生成、提交、推送或发布。
