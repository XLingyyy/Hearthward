## 01｜先解决“有系统、少体验”

*基线、产品问题与不扩大的边界*

将“可玩内容少、精致度不足”作为本轮产品输入。代码中有多少任务和物品，不能直接反驳玩家的实际感受；反过来，增加一批同质采集委托，也不能证明内容变丰富。建议把有效内容定义为：玩家做出一个有后果的选择，经历一段有辨识度的遭遇，或看到一次持久变化。

| 已存在的基础 | 本轮利用方式 |
| --- | --- |
| 8主线、15支线、4控制区、80基础驻军、最多8固定增援、10个救援人物 | 保留既有ID、人口与胜利分母。重做遭遇布局与任务表达，不用增加敌人数充当内容扩充。 |
| 60级、29技能、62物品、49配方；营地8阶 | 优先让现有工具、装备、图纸在不同场景发挥价值，不先叠加更高数值装备。 |
| 弟弟委托、手动任务卡、族人工作、双营地、持久状态 | 让分工减轻重复劳动，让救援与回营产生可见结果；新内容不强依赖自由语言成功。 |
| 角色、武器、火烟、步态和26事件/31引用WAV已整合 | 在当前版本上继续接触、混音、清晰度与场景统一，不重做已经解决的旧缺陷。 |

基线来源：[S02–S07]。约10小时首版和30–60分钟第一体验切片属于设计预算，不是已验证的当前游玩时长。[S03]

> 保持单人游戏、故乡夺回和第二营地边界。不加入联机、反攻敌方腹地、部族战斗小队、食物腐败、好感数值或两营地运输。新的剧情回访也不额外增加第11名可救援人物。[S03]

### 内容不足的四类原因要分开记录

找不到内容：修地标、线索和任务反馈。重复劳动过多：调整路线和分工。遭遇没有差异：重做场地、敌人组合和目标。奖励不明显：补营地外观、人物反应和工具用途。只有第四类也无法解决时，才考虑扩充系统。

### 四区必须读起来、打起来都不同

河口：水岸与开阔视线，选接近方向。作坊：遮挡与通道，决定接敌顺序。民居：巷道和观察点，重视撤退与救援净空。集会：较开阔的最终冲突，要求识别远程和重兵威胁。首先重排既有80驻军及固定增援的体验，不更改胜利分母。[S04]

### 空间验收

每个核心点至少两条实际可用的接近方式和一条清晰退路；每条路线均用正常输入验证玩家、弟弟与救援人物。美术只摆出“看起来能走”的侧门不算路线；无导航的装饰洞口要明确封闭。

## 05｜可直接下发的地点样板：旧渡口

*QN01「渡口留下的东西」／M1*

### 体验目标与前置

让玩家第一次体会“我去探索、弟弟负责准备、回营后有人回应”。在初始营地可用之后开放；不要求自由语言模型成功，不绑定强制资源等待。取回遗留物不增加救援人口，也不改动main_03中既有人物的归属。

| 步骤 | 实现与验收要点 |
| --- | --- |
| 1. 发现 | 用车辙、旧路标和渡口轮廓提供三个不同尺度的线索；不在未发现时直接给完整任务答案。 |
| 2. 观察并选择 | 浅滩路径较直接但暴露，高处绕行较长且有遮挡；只复用已有步行/涉水能力，不新增危险水流物理。 |
| 3. 兄弟分工 | 可给弟弟一个现有采集/搬运任务，或直接同行。两个方案都能完成，委托不是门票；手动任务卡和自然语言共用执行器。 |
| 4. 取得遗留物 | 从实际容器或交互对象取得唯一任务物；背包满时提供保留现场/腾出空间的明确路径，不丢失物品或伪造入库。 |
| 5. 回营回应 | 已救或初始族人回应物件来源；营地出现小型展示。奖励与展示绑定唯一事实，保存后不可重复领取。 |

### 失败、离开和读档

中途离开保留发现线索；物品取得前后分别保存并重启。若弟弟的工作受阻，显示已取得/已入库/剩余目标和停工原因，不把工作失败变成支线软锁。遗留物遗失处理优先复用已有任务物品保护；若没有相应规则，先提交设计决定，不静默传送物品。

### 制作交付与状态契约

交付：一张可走路线图、灰盒录像、入口/分叉/取物点/返营四张实机图、唯一容器清单、昼夜照明样板、环境音触发清单。建议稳定ID前缀poi_river_01与side_exp_river_01；采用前先查重。新事实优先复用现有Facts与奖励事务，若需要新持久字段则另做迁移契约。

> 验收不看“是否摆了渡口”，而看玩家能否理解两条路线、在分工期间继续行动，并在回营时识别一次真实变化。

## 06｜第二个制作样板：废弃炭棚

*QN02「没有带走的工具」／M1*

### 体验目标与前置

把一次取物任务做成可观察、可选择、可退出的短遭遇。围绕现有作坊外围制作，使用现有敌人兵种与物品，不引入开锁小游戏、爆炸生产链或新伤害类型。

| 环节 | 正面路径 | 侧路路径 |
| --- | --- | --- |
| 观察 | 从开阔入口看到主要威胁与工具箱位置。 | 从烟痕、破损围栏和光线找到侧面可走通道。 |
| 行动 | 在有退路的空间按现有战斗规则处理威胁。 | 利用遮挡靠近，采用既有潜行/击晕能力或等待巡逻离开。 |
| 弟弟参与 | 通过既有协助指令同行；明确等待或跟随。 | 安排弟弟在安全处等待，再带其通过已清理的路线；不新增双人同步暗杀。 |
| 取得工具 | 使用同一真实容器、同一唯一奖励事实。 | 同左。路线选择不能生成第二套工具或重复奖励。 |
| 回营结果 | 用取回工具触发已有设施的修复/陈列表现。 | 同左。非数值奖励也应有可见、可听、可查询的回执。 |

### 精致度要落在玩家经过的地方

优先制作入口木构、炭灰/脚印、工具箱轮廓、光源和角色接触。远离路线的屋后不先堆高精模型。交互范围、动画伸手距离和工具箱位置必须一致；无实际功能的设备不显示操作提示。

### 必须保留的限制

环境火烟只按已批准的视觉与声音规则使用；不得临时增加持续烧伤规则。巡逻单位的调整不能改变原80/84/88胜利分母，也不能制造无限增援。任何新路线若穿过流送边界，应单独验证弟弟等待/继续与读档。

> 核心验收：正常玩家能识别两条路线；战斗或潜行后都能可靠取得同一物件；返回营地有结果；整个流程存读档不重置奖励。

### 从现有支线中选择六条重做，不先武断替换ID

选择标准：最重复的三条采集/交付任务、两条找人或到点任务、一条后期经营任务。逐条先核对源代码的真实条件与现有奖励事实；改表达和场景后保留可迁移的稳定ID，不能为了新文案改掉旧档的完成身份。

| 旧结构 | 改造方向 |
| --- | --- |
| 拿N份材料→交付 | 观察线索→选择取得方式→真实交付→营地可见变化。 |
| 到某点→触发完成 | 读空间→选择接近路线→执行一段明确行为→获得可解释结果。 |
| 再升一级／再做一次 | 让该等级或设施解锁一个已制作好的场景用途；不增加空转等待。 |

主线保留8条结构，重点补足阶段间承接：为何离开营地、为何现在去救人、为何值得回营、夺回后为何还愿意停留。主线对白与动态自由交流分工明确；关键事实不依赖模型临时生成。[S03–S04]

## 08｜弟弟：可靠分工与角色存在感

*让伙伴参与玩法，而不是成为另一个操作负担*

### 四个可重复验证的分工场景

| 场景 | 玩家行为 | 弟弟行为与回执 |
| --- | --- | --- |
| 出发前准备 | 玩家整理装备并选路线。 | 通过现有任务卡取得/搬运明确物资；显示来源、目的地、数量和代价。 |
| 外出期间分头做事 | 玩家探索一个兴趣点。 | 在批准范围内完成一个安全目标；受阻返营并说明已经完成的部分。 |
| 救援与返程 | 玩家处理路径与威胁。 | 只使用已支持的跟随、等待、护送或施救；危险时行为可预测。 |
| 回营复盘 | 玩家核对收获并继续下一段。 | 用真实工作状态形成简短回执；未完成项提供恢复或取消入口。 |

### 表达便利不等于执行权限

自由语言继续经过候选与UE校验；任务状态、物资、未知地点和安全性来自世界权威状态。跟随、等待、取消、查询与确定数量操作保留不依赖模型的入口。新支线在模型关闭或失败时也必须能完成。[S08]

### 角色感来自情境，不来自额外生成次数

先制作少量高价值固定反应：第一次离开石堡、首次分工成功、受阻返营、救援成功、营地升阶、接近故乡、夺回、第一次在第二营地休息。用真实事件触发，读档不重复堆叠，同一上下文有冷却。固定台词与人声按既有批准范围验收；动态回复保持文字。

### 语言质量工程包

保留现有60题基准，另建至少30条未参与调优的同义表达与多轮补充集。分别记录原始理解、确认卡、最终执行、拒绝/澄清和玩家等待时间。不能把安全拒绝计为正确理解，也不能把暖请求组件时延当首次可见反馈。

> M1的伙伴成功标准：玩家愿意委托，并能继续玩自己的部分；不是输入一句话后盯着对话框等待。

## 09｜营地变得像“有人住的地方”

*8个有限事件＋3档外观＋第二营地*

| 事件 | 触发条件 | 可见变化／规则边界 |
| --- | --- | --- |
| E01 第一批带回的材料 | 一次真实入库完成 | 现有仓储附近出现对应的整理表现；不额外生成可领材料。 |
| E02 新住客落脚 | 既有救援人物真实到营 | 已有床铺/生活物件位置发生变化；不增加床位救援门槛。 |
| E03 工具归位 | QN02唯一事实成立 | 工作台旁出现工具与短对白；不免费复制装备。 |
| E04 火边一餐 | 首次合法用餐或规定阶段 | 人物坐靠、器具和火声组成短场景；不重复扣口粮或发奖励。 |
| E05 一次停工的说明 | 已存在的缺料/受阻状态 | 角色在合理地点等待，提示材料与恢复入口；不伪造事故损耗。 |
| E06 旧物的主人 | QN01或QN03交付成立 | 既有族人与取回物建立联系；不增加人口。 |
| E07 出发前的安静 | 满足返回故乡的主线阶段 | 角色位置与一次固定对话改变；不强制长演出。 |
| E08 归乡后的夜晚 | 夺回且第二营地可用 | 灯火、生活陈列和短回应形成前后对照；不新增敌人反攻。 |

### 三档外观复用现有8阶营地

1–3阶：临时床铺、零散器具、基本遮蔽；4–6阶：整齐储物、稳定作业区、更多生活痕迹；7–8阶：完善照明、分区和人物活动。分档是美术表现提案，不改变等级条件、产能、劳动力或全局加成。

### 第二营地的内容目标

QN05、QN06与E08完成“占领据点→重新生活”的转变。两营地继续共享仓储和等阶，建筑/岗位独立；展示变化必须与实际设施、人口、任务事实相符。展示状态优先由既有事实推导，不滥加存档字段。[S03、S05]

## 10｜战斗与奖励：增加决策，不增加打工

*保持既有战斗规则和胜利分母*

### 四种遭遇结构

| 结构 | 主要选择 | 制作重点 |
| --- | --- | --- |
| 观察后接近 | 开阔直达还是遮挡绕行。 | 敌人可读、路线有实际区别，观察点不是无意义高台。 |
| 处理威胁顺序 | 先压制远程还是先隔离近战。 | 射线、掩体和退路明确；不靠突然刷新背后敌人提高难度。 |
| 取物后退出 | 继续清理还是带目标物撤出。 | 退出条件与追击边界清楚，不制造必须杀光所有人的假选择。 |
| 受伤与救援 | 暂退、等待机会或让伙伴施救。 | 伤害提示、前摇、救援净空与取消反馈一致。 |

既有箭尖出箭、近墙遮挡、弟弟0.25秒前摇和步态接触修复已经实现；本轮检查它们在完整遭遇、坡地、不同武器和存读档后的稳定表现，不回退到旧问题列表。[S06]

### 奖励分成三层

即时层：真实物资、装备修复机会或已允许的图纸；中期层：更清晰的路线、更便利的现有生产设施用途；情感层：人物回应、营地陈列和故乡前后对照。一个地点不必同时发三种奖励，但至少要让玩家说清“这趟为什么值得”。

### 经济检查

在确定道具奖励前核对现有配方与价格。所有新增一次性奖励使用唯一事实；不能用多次触发、容器重载、两营地重复领奖或睡眠刷新刷出收益。新物品只有在现有62物品无法承担明确用途时才提案，不先造一排同属性换皮武器。

> 优先打磨一个正常一对三遭遇，再扩到四区。任务数量与击杀数量都不是战斗深度的替代指标。

## 11｜视觉精致度：按玩家注意力排序

*沿用已批准的山地石堡、旧木、自然材质与火烟方向*

| 层级 | 本轮制作内容 | 验收方式 |
| --- | --- | --- |
| 近景：角色与交互物 | 手握武器、接触点、脚落地、施救距离、容器和工作台操作；修材质尺度和明显穿插。 | 固定距离、待机/走跑/攻击/采集/施救连续片段；主角与弟弟分别验证。 |
| 中景：玩家主要路线 | 入口、门框、路面、地标、光线引导；卧室→撤离、营地→第一兴趣点、回营三条路线先统一。 | 白天/夜间、往返两向、正常摄像机；不只交无HUD的好看截图。 |
| 远景：轮廓与世界层次 | 四区轮廓差异、山脊识别、地标对比、距离层次与稳定LOD。 | 相同机位与画质对照，移动中检查跳变和消失；不凭更高面数通过验收。 |

### 统一而非堆细节

同一类石、木、布采用一致的尺度、粗糙度与磨损逻辑；道具应有人使用的摆放关系。灯光优先服务路径与交互识别，不能只靠全局抬曝光掩盖暗角。火、烟、衣料和草地同时出现时检查视觉层级，不让装饰盖住敌人前摇和任务目标。

### 首件冻结顺序

先批准一个入口、一间生活内室、一套营地工作区和一段角色完整动作；随后复制材质和制作规范，而不是整批制作完再统一返工。每个首件同时交近景质量、可走性、声音、运行成本和来源台账。

### 资产性能约束

按屏幕占比、材质槽、阴影和实例数量做预算。石斧已有约95,278渲染三角面记录，值得审查，但本次没有改资产，也没有证据说它是低帧率唯一原因。减面、烘焙或LOD必须保留轮廓、握点与刀刃插槽，并取得实机对照。[S07]

## 12｜声音与界面：把完成感补出来

*听得到状态变化，看得懂下一步*

### 音频先混音，再扩事件

现有26事件、31份引用WAV是可用基础，不等于设备混音已经合格。本轮优先检查五类脚步接触、落地、进出水、火焰和局部风声的远近变化、循环接缝、重复感与同时播放的遮蔽。固定对白仍按真人录音范围制作；动态回复不新增TTS。[S02、S07]

| 场景 | 需要清楚传达的信息 | 交付检查 |
| --- | --- | --- |
| 经过渡口 | 脚下地面和入水变化；远处风不压过重要提示。 | 移动连续录屏与设备实际声音，覆盖岸边反复进出。 |
| 作坊与营地 | 火焰、工作与完成回执有层次。 | 开关工作、离开再返回、暂停、读档不叠加循环声。 |
| 战斗与救援 | 受击、出箭、攻击前摇和施救完成能被区分。 | 不是每种事件同样响；关闭声音时仍有等价视觉信息。 |

### 界面精修清单

交互：只为当前可做的操作显示提示；任务：区分目标、当前位置和下一步路线；背包：拖放前后身份、数量和负重可核对；制作：缺料项与来源明确；伙伴：已完成/已入库/剩余/停工原因分开；存档：当前进度、节点和确认行为没有歧义。

### 可访问性与输入

至少在1080p和150%界面比例下检查文字、按钮、滚动与确认框；补中文输入法组合、Enter/Esc优先级、窗口切换和重复打开关闭。重要信息不只靠颜色或声音。默认字幕可读，运动与亮度相关设置不被读档错误覆盖。

> 新增内容的完成提示必须让玩家知道“世界改变了什么”，而不是只闪一下“任务完成”。

### 新增的产品指标建议

首段引导：至少4/5名玩家无需口头提示找到下一步；分工：至少4/5名玩家能正确说出弟弟正在做什么、资源最后去哪；内容记忆：至少4/5名玩家能描述两个不同兴趣点的区别；回营反馈：至少4/5名玩家能指出一次营地变化。小样本只用于发现问题，不作为总体满意度统计。

### 节奏记录

分别记录观察、选择、战斗、探索、营地管理、纯赶路和等待。建议把主路线连续数分钟只有行走/重复采集的片段列入审查；氛围留白可以保留，但应有明确意图。新增有效时长只记录第一次完整体验，不用重复劳动填充。

性能旧结果与限制见[S08–S09]。20项本次工具测试仅覆盖工具逻辑；7项新增UE测试、全仓65项既有工具测试、UE编译、实机与真人验收在本会话均未运行。

### 资源分配建议

以每100份可用制作容量计，先分配约30份给现有内容的玩法与导航，25份给角色/首线场景精修，20份给新兴趣点/支线，15份给工程与回归，10份给声音/文字与整合。比例是预算建议，不是工期估计；若稳定性门槛不达，先从新增内容额度转移，而非削减回归。

> 限制同时在制：一个核心地点、一组近景美术首件、一条工程优化线。避免十几个半成品一起进入整合，最后无法判断谁导致了卡点或性能回退。

## 16｜风险、取舍与发布门槛

*做什么，也明确暂时不做什么*

| 风险 | 控制办法 |
| --- | --- |
| 地图更满，但仍然无聊 | 每个地点至少有观察/选择/反馈之一；没有独立体验的点合并或删除，不保留作数量。 |
| 新剧情依赖不可靠模型 | 关键条件、固定对白、任务卡和回执确定性实现；自由语言只是另一种入口。 |
| 美术提升拖垮性能 | 首件同时测镜头、阴影、材质与加载；发布前以真实Shipping和原画质比较，不暗降门槛。 |
| 新奖励与旧档冲突 | 稳定ID查重、唯一事实、正式迁移检查；原件只读备份，副本验证。 |
| “救人”变相突破人口上限 | 使用初始族人或已救人物回访；不加第11个额外救援，不改变床位规则。 |
| 资产来源不完整 | 先补来源/条款/输入授权链；无法闭合的资产进入替换清单，不能把UNKNOWN默认视为可发行。 |
| 工程结果被过度宣传 | 源码、工具测试、UE编译、Shipping、性能、人工分别列状态；不宣称本次已提帧或已修改远端。 |

### 本提案的默认取舍

优先在既有世界内补内容，而非增新地图；优先明确任务和分工，而非更复杂自治；优先原有武器/动物/设施的用途，而非更多同类条目；优先玩家会接触的近景，而非远景资产堆量。

### 进入生产前需要产品负责人定案的变化

批准M1范围和两个地点首件；选定6条旧支线重做对象；批准新短支线的具体奖励与固定对白；确认第二营地变化仅表现还是包含新的设施功能。未定项保持提案，不由工程代码擅自落成玩法规则。
