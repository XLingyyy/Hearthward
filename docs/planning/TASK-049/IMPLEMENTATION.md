## 稳定身份与状态

- `main_01…08`、`side_01…15`为新正式任务；旧ember等ID留在legacy_demo命名空间，避免把旧领取经验当作已完成新剧情。
- `home_<zone>_<ordinal>`为80基础驻军；两组 `reinforce_<zone>_<ordinal>`最多8人。注册集合保存于世界状态，不能依赖当前加载的Actors。prologue／field／protected身份不加入故乡分母。
- 每任务使用 `reward:<quest_id>`；物品里程碑沿既有key，知识沿已有知识账本。任务奖励、来源交付、人口登记均校验epoch及事件ID。同一事件重试不再扣料／加经验／加人口。
- 救援状态：uncontacted→waiting／following→arrived。危险或不可达可following→waiting，恢复后由玩家继续，不产生新Person。只有arrived进入Rescued；先登记人口后发奖励失败需整体回滚或持久待交付事务，不能重新登记第二次。
- 任务状态：hidden／available／active／ready_to_claim／claimed；选择顺序、日志追踪不改变世界胜利。永久胜利事实优先于日志线性顺序，未领奖不是世界锁。

## schema7旧档到未来正式剧情版本

1. 先验证旧世界各模块。保留库存、耐久实例、经验、技能、口粮、设施、自然资源、旧奖励及全部旧档；不用读取时间作为刷新起点。
2. 旧自然营地进度设置phase=camp_established、prologue=skipped_legacy；main_01不可补经验。后续主线可以进入main_02，不能因main_01未领奖一直锁住。
3. 旧Demo11任务保存为legacy历史，领取入口关闭且已领经验不撤销。正式任务的已完成事实只从相应真实持久状态映射：工作台、营地等级等可认领；旧watch／旧击杀／日志计数不可冒充新关卡事实。
4. 若旧档已有Rescued中的陌生ID，不能再给全10名救援者导致超过30；迁移前审查其来源。合法正式已救ID逐一映射；仅开发夹具产生的未知ID必须报告兼容阻塞，不默默删人口、重发奖励或把它变成新的官方角色。
5. 若旧档已有Hometown=true却没有正式驻军／四旗账本，保留既得第二营地和奖励；单列legacy_hometown状态，保留旧可玩行为，正式四区不得生成敌人覆盖既有安全营地。是否提供可选新战役需Owner另定，不擅自剥夺胜利或伪造80个击杀事件。
6. 新档的80初始驻军只在occupied阶段第一次注册；保存点含配置版本。重载、传送、四日刷新都不重复注册。旧档迁移后第一次保存需可回读，再开放输入。
