# TASK-024｜工作台装备维修与耐久回档

用户授权“继续024，自己提交推送”。从023的 `d33e6a78d91e5faf82f22d18d6d07c87a1ab04aa` 堆叠，分支 `codex/TASK-024-workbench-repair`；范围提交 `0f9a3780965e264a70605859462465d48a51ff4c`。实现提交绑定见证据目录working-tree-binding.json。未合并main，未执行004，用户验收待定。

## 使用

- 靠近已建工作台按E，在制作页点击“装备维修”。背包选装备后H也可跳转维修页，需处于工作台使用范围。
- 装备按损坏程度优先列出，滚轮浏览。选择装备查看耐久、修复后数值及木材/绳索的持有和消耗量；F或按钮确认整件修复。满耐久、缺料、不支持或不持有的物品不能修理。
- “制作物品”切回制作页，可先制作绳索。返回按钮回游戏；PIE用按钮避免编辑器Esc停止Play。
- 三个独立面板/操作组件组支持F10移动、缩放、隐藏，背景无烘焙控件。目前14页59组。制作页列表改为每屏4项，避免扩展配方后覆盖新增维修入口。

## 结算与边界

- 复用023工作台稳定ID、实体/距离/视线、健康/战斗/持续动作及epoch校验。旧维修API委托到同一结算入口；背包H改为先预览，防止没有费用说明就直接扣料。
- 9类现有带耐久装备各有repairRecipes；护符没有耐久配置，不参与维修。配方只用可获取木材和绳索，不再要求尚无正常采集入口的矿石。原型石斧2木材1绳索、猎弓1木材2绳索，其余见JSON。
- 全修费用是独立PROTOTYPE_ONLY数据；20%制作成本、取整、局部维修、不可自制战利品维修仍待R13/R14明确。本单没有伪造装备制作表，没有新增稀有装备或永久装备规则。
- 延续现有按物品类型保存耐久的模型，未引入同类装备实例ID；不宣称已支持同类多件装备各自耐久。当前防具损耗与破损效果沿用020原型。
- 原子材料扣除前暂设目标满耐久，扣料失败回滚；成功库存通知观察到完整材料及耐久状态。Settling覆盖通知及维修事件，避免重入维修或保存半个结果。缺料、满耐久或访问失效不扣任何材料、不记事件。
- 物品、耐久与维修事件沿用现有存档字段，不改变保存格式。读档废止旧会话、恢复三者，重复加载不重放维修。
