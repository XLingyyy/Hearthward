## 实现范围

1. 显式启用的非Shipping伙伴夹具：同一快照保存玩家位置/视角/背包/计时、共享仓储、伙伴/营地/资源点位置、有限资源、携带物资、委托阶段/实际入库量/采集计时、世界累计时间和原始交流记录。
2. 加载校验成功后在游戏线程一次性恢复；重新生成运行epoch和恢复任务的执行票据，取消未完成推理、清除未来回复/上下文和UI草稿；保留快照中的委托进度。
3. USaveGame schema 1；全原型进度共用一个最多50点的池，只有最早未锁自动档可轮换。手动和锁定节点受保护；满额全保护时，新进度要求玩家主动腾出位置；有可替换自动档时可按同一轮换规则建立初始节点。列表含进度、节点、时间、地点、夹具阶段、类型与锁定状态。
4. 自动档默认10实玩分钟，可设1—60；暂停冻结。六类已确认危险由显式测试标志提供，危险时延后；严重饥饿可存并提示。生产危险检测及R22仍未完成。
5. 写入临时文件、回读校验后使用Windows原子替换；临时文件不列为额外回档点。损坏/不兼容档明确拒绝，不静默重建空档池。

这是一份开发快照格式。新进度初始位置和数据来自启用时明确准备的夹具，未决定R22正式初始节点位置。读取另一个PIE的节点需要先创建同一伙伴夹具；地图不匹配时明确拒绝，不自动切图或实现任意实体重建。
完整GDD中的生命、技能、建筑、敌人、旗帜、藏宝图等系统尚未实现，未伪造快照字段或宣称验收。当前独立交互目标未接存档，进行中的交互拒绝保存；额外未注册容器也拒绝保存。
知识保存原始玩家说法和已显示弟弟台词，近期最多8条（合计512字符预算）进入标注为不可信的模型上下文；不把台词升级为世界事实。完整可编辑知识清单、长期约定索引和Embedding仍待后续任务。
小规模夹具采用同步捕获/写入，避免异步模块版本混用；正式大世界后台写入和性能预算留待实际模块接入后评估。退出无额外隐藏档。
