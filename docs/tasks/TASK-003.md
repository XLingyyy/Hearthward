# TASK-003 建立第三人称灰盒行走基线

状态：Backlog，尚未实施。任务快照：[TASK-003.json](TASK-003.json)。
负责人、独立评审人、GitHub Issue：待分配；拟用分支 `codex/TASK-003-third-person-bootstrap`。

## 一个交付目标

在 Hearthward 仓库根建立 UE 5.8.1 C++ 工程，让玩家在一张独立灰盒地图中实际控制第三人称角色行走并转动镜头。交付一条可重复的“编译 → 打开地图 → PIE → 操作 → 退出”路径，为后续交互和伙伴任务提供运行基础。

这是从 TASK-000 拆出的首个工程实施项。本轮只建立任务单；完整 M0、正式玩法和其余系统各自验收。

## 设计来源与选择理由

- [GDD v0.3 原件](../归火Hearthward游戏设计文档_v0.3.docx) 第1.1章／Q002确定单人第三人称；第3.1章／Q004要求开场能实际操作。可通过[历史版提取文](../design/archive/gdd-v0.3-source.md)检索相同玩法条款，版本差异见[设计入口](../design/CURRENT.md)。
- 第4.1章、第16章／Q177已接受常态速度 3.5 米／秒，属于 INITIAL_TUNING；UE 默认厘米单位下为 350 cm/s。
- 第17章的 R09 尚未闭合耐力恢复时钟，R23 尚未形成完整输入表，R24 尚缺高级通行参数。本任务只做平地行走与镜头，保持这些未定项 OPEN。
- 当前仓库没有 .uproject、运行模块或地图。先建立可运行基础，不依赖库存、伙伴或存档草案契约，也不等待 TASK-000 的两机验证全部完成。

## 实施范围

1. 根目录建立 `Hearthward.uproject`、Hearthward 运行模块及 Game/Editor Target。两个 Target 使用 `BuildSettingsVersion.V7`，EngineAssociation 为 `5.8`。不在仓库内再套一层项目目录。
2. 复用 UE 自带 Character、CharacterMovement、SpringArm、Camera 与 Enhanced Input，建立最小 GameMode、角色和输入。优先沿用可用模板／引擎组件，不自建移动框架。验证采用 WASD 行走、鼠标转镜头，键位仅用于本任务，正式输入表仍待 R23。
3. 在 `Content/Hearthward/Bootstrap/` 建立 `L_Bootstrap`、PlayerStart、平地、碰撞墙与照明。使用引擎基础几何体或已有可分发模板资源，不下载美术包。此地图不承担正式营地或夜袭关卡。
4. 行走速度上限为 350 cm/s。镜头距离、转动灵敏度和灰盒尺寸采用可调整的工程初值并记录；不把这些初值写成正式设计。
5. 从本仓库显式指定工程路径进行编译与启动；引擎生命周期走 GameFactory UEClient。确需框架插件时仅安装本地已有 A3GamePlayable，并记录来源版本；不为将来功能安装额外插件。更新工具链中的实际工程路径及构建说明。

允许／禁止修改路径以 JSON 为准。工程根配置和基础角色属于共享文件，本任务开工时须确认唯一写者。
新增二进制资产预留独立目录，保存后按工作流加 LFS 锁并记录 ID；锁保留至合并验证或明确弃用。

## 验收步骤

| 编号 | 实际操作 | 通过条件 |
|---|---|---|
| A1 | 用锁定工具链构建 Development Editor / Win64 | 实际进程退出 0；记录命令与日志，不能用仅生成项目文件代替编译 |
| A2 | 打开 L_Bootstrap，进入 PIE | 生成并控制第三人称角色；镜头显示角色和场地；无缺失引用或项目阻断性错误 |
| A3 | 前后左右、斜向行走，转动镜头，走向碰撞墙 | 输入正确；不能穿墙；稳定平地速度为 350 cm/s，斜向不加速 |
| A4 | 释放输入并再次移动；退出后再次进入 PIE | 角色正常停下／再移动；两次 PIE 均可控制，无崩溃或残留输入失效 |
| A5 | 整理同一提交的证据与必要资产 | 记录 tested_commit、工具版本、地图、操作步骤、实际速度和日志；附短视频或连续截图；资源被 Git/LFS 正确跟踪 |

A3 测量在加速结束后的平地稳态进行，以 CharacterMovement 实际速度或坐标差／实测秒数记录；允许测量误差 ±5 cm/s，误差是测试容差，不调整设计速度。
最小验证为一次 Editor 编译、上述 PIE 操作及本任务路径检查。没有新增独立复杂逻辑时不为模板类机械添加单元测试。
参考 Epic 的 [Automation Test Framework](https://dev.epicgames.com/documentation/unreal-engine/automation-test-framework-in-unreal-engine)：后续需要自动测试时复用引擎测试框架；本任务不提前搭建独立测试平台。
