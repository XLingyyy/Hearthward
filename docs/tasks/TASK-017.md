# TASK-017｜存档管理与退出确认界面

依据当前设计原件第13章（Q139—145、Q262—265）和第14章存档区、不可用原因要求，衔接016已实现快照。用户授权自行拆解并推进017。

## 范围

原生UMG存档列表与详情，显示所有进度共用容量、所属进度、UTC保存时间、地图、阶段、手动/自动及锁定。手动保存、读档、新进度、锁定/解锁、删除、自动间隔通过UHearthwardSaveSubsystem；危险原因由保存模块读取真实夹具状态。加载、新进度、删除及退出采用显式确认；退出提醒未保存进度丢失，不创建额外节点。

F6为非Shipping临时入口，沿用灰盒夹具；未创建夹具时显示实际不可用原因。面板暂停，保留已有外部暂停；与背包/交流互斥，关闭恢复键鼠。两栏布局沿用015的深色、暖白、金色原生UI，适配1280×720及1920×1080。

不变更存档格式、50点规则、地图资产及R22/R23；不将开发入口称为正式开局/地图切换。菜单的新进度仍使用016显式启用时的初始快照。

## 验收

- 空池与50点滚动列表、所有元信息、保护/满额/危险原因和1—60分钟设置。
- UI调用真实存档接口完成保存→改变库存→确认回档，世界/进度/时间线一致；重复与取消操作不额外执行。
- 删除确认绑定原节点；新进度、读取、退出取消无副作用；锁定不被自动轮换。
- 暂停时钟、既有暂停保留、面板互斥、Esc/F6关闭、Tab背包、鼠标选择及操作、两轮PIE重启。
- 构建、原生Save测试、两轮PIE集成、实键录像及截图检查；最终记录实际覆盖范围。

实现仅需UI及保存模块少量只读查询/提示，详见JSON允许路径。正式Issue/独立评审尚缺；本地实现授权与流程审批分别记录。
