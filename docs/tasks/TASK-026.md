## 3. 尺度与空间规划

以下为本任务提出的首轮工程目标，尚非用户批准的最终地图参数。本地灰盒已按4.032 km World Partition方案实现用于验证，但该事实不等于Owner批准最终尺度或视觉方案。GDD未定项保持OPEN，不通过本任务单自行关闭。

| 项目 | 首轮规划目标 | 验收口径 |
|---|---|---|
| 地形范围 | 约4 × 4 km，约16 km² | 示例为4033 × 4033高度采样、XY间距1 m，实际边长4032 m；边界、单位和高度范围写入地图说明 |
| 连通可探索地面 | 至少6 km² | 总体图提供可行走范围掩膜/多边形及计算方法；陡壁、深水、远景山体不计入 |
| 自然分区 | 林地、开阔草地、河谷河岸、丘陵、山地至少5类 | 是同一连续地貌中的视觉与空间分区，具有自然过渡，非5张孤立展示场 |
| 水系 | 至少1条有上下游关系的主河道，1处较宽水面或天然汇水区 | 河床、岸线和山谷高程合理；至少2处可步行浅滩或陆路绕行连接两岸 |
| 通行结构 | 1条跨越上述分区的主环线，总长至少4 km，另有至少2条支路 | 使用现有角色正常移动实测，记录路线与耗时；不得依赖传送、飞行或尚未实现的游泳/攀爬 |
| 视觉地标 | 至少3处远距离可辨认的自然地标 | 例如山脊、岩壁、河谷转折；提供观察点和视线关系 |
| 后续布置空间 | 隐蔽营地、故乡/第二营地各预留1片候选自然缓坡或空地 | 仅记录候选坐标、可用面积、坡度和进出方向，不确定最终营地半径、建筑布局或四区边界 |

采用合法 Landscape 分辨率与合理组件数量，先以小面积样段验证精度和性能再展开全图；不得为实现表格数值直接放大灰盒平面或以不可到达背景填充可探索面积。若目标硬件无法支撑，记录瓶颈并先调整密度、LOD、流送与材质；改变上述尺度/面积目标需更新方案并由 Owner 确认。

洞穴可作为额外自然空间，本轮不要求复杂洞穴网络；一旦摆放可进入洞口，就必须有完整的内部碰撞、照明和可返回路线，不能以空洞或掉落虚空交付。

## 4. 实施范围与顺序

### A. 自然资产盘点与必要适配

1. 逐件建立“已有源文件 → UE可用 → 场景使用”的清单，包含源路径、资产ID、许可记录、模型/材质依赖、缺口和处理状态。读取004两份 `SOURCE.md` 与资源汇总，优先使用现有素材。
2. `.blend` 经现有可用工具导出；草和树叶选合适LOD、Masked材质、实例密度和剔除距离；树干/岩石使用简单碰撞。处理缺失法线/材质引用，GL法线方向与数据贴图颜色空间；限制不必要的4K/8K常驻纹理。不能将百万面草木直接全图散布。
3. 缺少水面材质、地形混合材质或必要岩壁时，可在026专用目录制作最小可用环境资产。新增外部资产按来源、许可证及成本单独登记；不扩展为全资产库重做，不擅自付费或安装大型生成环境。
4. 复用004既有原始素材只读；026转换/减面/导出的派生源保存在 `art_source/TASK-026/`。已有合格UE资产只读引用，新的自然适配资产放026专用路径，避免004与026重复编辑同一资产。
5. 蓝花楹、岛树仅为 `TEMP_VISUAL` 候选，统一当前偏写实自然表现，避免混杂明显冲突的尺度、色调与气候意象；具体植物群与地理设定仍待后续设计。Sketchfab已有Owner入库许可确认无需重复索取，但原始页面、作者与具体条款缺失须如实记录，不宣称已完成发行许可审查。

### B. 总体地形与水系

先交付一张带比例尺、北向、边界、标高、分区、水流、步行路线、自然地标和后续候选空地的总体图，再建立 Landscape。先完成山脊—谷地—汇水关系、坡度和主要通路，再做地表材质与植被。

地形应具备大尺度山谷、中尺度坡台与近景变化；草/土/岩面按地貌混合，降低明显平铺。河道顺地势流动，水面贴合河床，岸边有过渡；远景轮廓与近处地表连贯，无直线切边、裸露方形地形或重复噪声山包。不要求流体模拟、侵蚀系统或动态天气。

水体只承担环境表现。本轮通行靠浅滩与陆路；深水边界结合地形和明确限制处理并记录，不新增溺水、游泳耗耐、坠落伤害规则。限制区不可出现无提示的穿底或不可返回卡死。

### C. 植被、散布与环境表现

根据坡度、高度、水岸、林缘和开阔地建立有疏密变化的分布；保持主通路与候选空地可通行。树、灌木、草和石块形成层次，避免等间距网格、随机噪声式撒满全图、悬空树根和大面积穿插。

优先使用引擎已有 Foliage/实例化与 Landscape 工具。PCG仅在确有收益且依赖已批准时使用，固定种子并记录生成范围，重建不得覆盖人工修整；不为本单开发新的地形或散布框架。设置统一天空、大气、日照和雾，至少验证一个清晰可读的日间基准，不以浓雾掩盖空白区域。

### D. 大地图组织与运行入口

- 建议新建 `/Game/Hearthward/World/Natural/L_NaturalWorld`，优先使用 Landscape + World Partition；按照工作流第7.3节先记录工程决定及Owner确认。OFPA、外部Actor、Landscape代理、HLOD和Data Layer依赖纳入交付。
- 自然地形、水体、植被、岩石和环境照明分层管理，提供后续人文布置的层/目录约定。候选空地标记使用编辑器可见对象或地图文档，运行中不显示开发标牌。
- 流送范围和远景代理根据视线与实测设置；按资产类别验证LOD/Nanite/HLOD选择，不能假定所有Landscape、植被都会自动得到合适代理。验证跨分区移动后的加载、卸载和远景连续性。
- 通过独立地图入口和地图级配置复用现有第三人称移动。需要隔离时，在本单目录创建仅用于浏览的 GameMode 蓝图并复用现有Pawn/Controller；不得自动进入020开发玩法、生成营地/敌人/资源、启动本地模型或读写正式存档。
- 保留现有 Bootstrap 和 Graybox、默认新游戏/继续游戏入口。本单交付明确的“打开地图→PIE/Standalone”操作说明；未来把正式游戏入口切换到新世界另行协调。
- 玩家通行必验；伙伴完整大世界导航、跨流送任务和采集行为留后续集成。记录主要通路净宽、坡度及潜在导航风险，不把现有小场景导航验证外推为大世界能力。
