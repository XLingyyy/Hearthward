# DSGN-001 本机模型与轻量检索推理链

状态：APPROVED（设计方向）；批准人：XLingyyy；日期：2026-09-18。
批准依据：用户指定013接通真实模型、在玩家电脑运行，候选Qwen3.5 4B，路线UE→llama.cpp→GGUF→Qwen，并要求将原两层LLM架构同步改为轻量前置与一次4B推理。
此批准覆盖架构与部署方向；不等同于Issue/代码审查完成或所有目标硬件性能通过。

## 生效口径

玩家输入 → Embedding、规则或轻量分类 → 意图候选/置信度、RAG检索、游戏状态可知性过滤 → 单次4B LLM → 结构化结果与NPC文字台词 → UE校验和真实执行。
前置层可以输出unknown或多个候选；有歧义时澄清，不能为了“确定intent”强行选择玩家未表达的目标。
Embedding、规则和轻量分类按工程效果组合；不强制再常驻一个生成模型。013首版采用规则意图提示与按主题/词项排序的检索，暂未加入Embedding模型。

结构化结果必须通过schema和领域语义检查。模型没有直接写库存、建筑、战斗或存档的权限；UE复核对象、安全权限、距离、材料、命令代次和时间线。取消与迟到处理保留现有防污染规则。
知识按初始知识、玩家表达与实际世界事件区分；角色不知道的营地变化、隐藏目标、未来存档信息不得通过检索或后台状态泄露。玩家输入、知识文本与模型输出均不能提权为系统规则。
全局三条建议只在主动刷新时更换，未选中的新信息不进入弟弟认知；30米交流、安全独立任务、一目标最多三步、多趟实际交付均保持。

## 部署与候选

UE启动项目内的llama.cpp本机推理进程，加载随游戏分发的GGUF权重。玩家无需Python、独立模型管理器或云端账户；运行时不联网下载模型、不上传对话。
当前候选为Qwen3.5 4B；013核验Unsloth提供的Q4_K_M转换版本、固定llama.cpp构建与来源。具体版本、散列和量化见config/local-ai.lock.json，属于工程锁定记录。
CPU兼容路径与GPU卸载按玩家硬件和游戏显存预算配置。上下文、并发、输出预算需要限制；异步加载/推理不能阻塞游戏线程，启动失败、缺文件和超时须明确反馈。
性能以实际目标硬件报告为准。嵌入游戏目录不等同于将大权重上传源码Git；发行包须包含模型、运行库和相应许可，源码提供固定版本的可复现准备步骤。
