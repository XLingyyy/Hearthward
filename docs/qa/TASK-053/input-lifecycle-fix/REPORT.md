## 原因与修复

1. 加载层记录了进入加载时的 `GameViewportClient::IgnoreInput`，标题／暂停的UIOnly模式会将它设为true。新地图已切到HUD后，加载结束又恢复旧true，造成画面正常而全部游戏输入被丢弃。现在加载结束依据当前页面统一恢复暂停、输入模式、鼠标和焦点；加载期间切到HUD仍保持输入阻断。
2. 角色绑定初始化原先无条件写GameOnly并隐藏鼠标，可能覆盖新标题UI的焦点。现在角色初始化沿用当前界面输入模式。转场前释放UI自己持有的暂停；登录地图加载不等待暂停世界的玩法／纹理流送，也不冻结无关角色；登录页特殊处理仅限L_Bootstrap，其他地图沿用其自身HUD，不强求主UI。地图失败和存档兼容错误清除加载遮罩并返回可操作界面。
3. 自然地图仍要求地形碰撞、World Partition和序章准备就绪；全局纹理请求在世界就绪后最多额外等待五秒，余下视觉资源继续后台流送，避免内存预算下长期有待加载纹理而锁住输入。未降低地形就绪条件。
4. 日志Q/E分类键加入实际键位定义、重映射与同场景冲突检查。方向、翻页、Home/End作为界面导航保留键；快捷键按当前页面上下文匹配，标题页不会被游戏快捷键带入未启动界面。M/K/J/B支持再次按键关闭；Tab背包、F6存档、P暂停、T交流及Esc返回均保持有效，地图Tab继续承担按钮导航。
5. 菜单暂停设置应用后立即更新当前页面暂停状态，未应用草稿返回时丢弃。设置／存档／暂停嵌套返回恢复正确父页面。维修F键原指向被行装管理替代的旧repairing页面，现接到equipment页现有“全部修复”动作；原选中装备、材料与设施条件继续由同一操作校验。
