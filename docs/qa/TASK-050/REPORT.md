Owner／Reviewer：XLingyyy。真实TASK-050对应原稿052；D1—D6已批准。受测分支 `codex/TASK-050-companion-design`，基于已含049的 `main@3a163b9`；首批受测代码提交 `f008e19d48bf61ae99cd878a0c37e515097753d8`，本页记录后续能力增量。任务进入Owner验收；无Issue，不合并main。下列结果只约束所列场景与源码。

## 本次可执行范围

- `store`接管弟弟背包已有的普通可堆叠物品，也支持玩家在同一营地、双方相距3米内按任务卡当面交付。交付后物品真实进入弟弟背包，返营后按实际入库记完成，不把旧货物记为新采集；无法返营或入库时保留物资。现有仓库无常规容量上限，不能用此场景证明“仓库只剩4份容量”的分趟要求。
- `retrieve`从当前营地仓库经唯一存储服务取普通可堆叠物品，弟弟按背包容量分趟搬运并交入同营地玩家背包。存档中的取货／携带／交付数量分开；玩家离营或交付受阻时返仓的货物不计交付；不再位于弟弟背包的货物记短少，不推断去向或伪造返仓。玩家必须明确说出仓库与交给玩家，或逐项确认手动任务卡。
- `give`把弟弟背包的普通可堆叠物品直接交入同营地玩家背包，按真实转移量累计完成。玩家背包满时，余货仍留弟弟背包；中途存档恢复后须由玩家明确继续。确认新委托替换未完成旧委托时，旧委托记终止，防止记忆中同时出现两个活跃任务。
- `fetch`从当前营地仓库取普通可堆叠物品留在弟弟背包；`receive`从同营地玩家背包接收普通可堆叠物品留在弟弟背包。两条路线按真实进入弟弟背包的数量计完成，容量不足时原容器中的余货不动，部分完成的计数与背包状态可存档恢复。
- `nature_collect`仅接受唯一资源点ID、玩家在目标30米内明确指认及弟弟有可用工具的委托。同营地资源可直接执行；营地外目标另查可达营地归路、真实存量和沿途野生动物威胁，未知或不安全目标拒绝。每轮沿Nature既有`CommitCompanion`入口真实扣资源／工具耐久并按剩余目标和背包容量限制产量，返营后另记入库数；弟弟采集不会记作玩家个人采集或矿点剧情进度。
- `nature_care`只接收唯一已知地块／栏舍ID，支持地块浇水、施肥、成熟收获以及栏舍投入饲料。任务卡先确认，弟弟执行五秒动作，Nature原有结算入口扣料／产出，回执按动作次数记账。未成熟、已做或缺料由领域状态拒绝，不由模型造物。
- `repair`可在手动任务卡选弟弟持有的明确EquipmentId；同类多件不随机选第一件。卡片显示所选实例耐久和按当前磨损计算的预计费用，提交时复核材料与实例。旧无ID目标仍只接受唯一同类实例。实例身份和耐久随schema8存档恢复。
- `craft`与`repair`现按配方要求选择同种类、足够等级的已建设施。伙伴经现有Workshop服务执行限定批数，材料与产物由真实背包／仓库事务结算；已完成或取消的旧任务不会永久禁止弟弟恢复046在岗工效。持续在岗队列仍由046独立结算，不会因任务额外复制一份产物。
- 已建栏舍的成年、入栏且有已支付饲料窗口的家鸡／山羊分别以1440W分钟产1份鸡蛋／羊奶，每栏最多暂存24份，断粮、幼体或未入栏不产。玩家可从栏舍取回；弟弟按明确目标和数量从同一Nature事务入口收取、背包携运并实际入库。新字段随Nature状态保存，旧档不追算历史产物；家猪仍只产肉，自动宰杀未开放。
- `escort`限定玩家已接触的救援者与当前营地，救援者跟随弟弟实际移动并到营报到后才记人口和完成；`hunt`限定已指认野生动物，弟弟用真实武器命中击杀，尸体掉落由Nature结算；`fish`限定已指认鱼点，弟弟鱼饵、鱼竿耐久、鱼群库存和渔获经Nature结算；`capture`限定已指认家畜及同种空栏，新捕获实际扣饲料与绳索，弟弟牵引至栏舍后才计完成，未入栏只保留捕获状态。这四项需要玩家同行，超出30米暂停并会合，不自行换目标。
- `camp_batch`限定已配置的同营地设施区域、已解锁配方、只有弟弟在岗且队列空闲、共享材料足够的情形。弟弟到岗后由046原有区域事务按投入与产出结算；区域记录绝对批次上限，长时间推进也不会启动未授权下一批。完成量和任务回执跨存档恢复；手动停产、材料不足或危险状态保留在途批次与材料，不另发一份产物。
- 已确认的规则按约束类型与物品替换同一槽位；`allow:物品`只解除后续禁用，`once:物品`仅对明确本次的任务跳过对应禁用，其他预算保留。记忆页一张确认卡列出执行中的任务、未确认候选和玩家规则，确认后统一取消；玩家陈述、事实、回执与货物保留。确认前后复核30米、任务ID、记忆修订和时间线。
- 三日交流按W计4320分钟。新进度及首次会合前保存的节点等到兄弟首次进入30米后起算；旧档缺计时字段则以载入W起算。同一安全营地、可交流、无战斗／对话占用时给一次短提醒，回营与存档状态按规则恢复。救援中断消耗性活动后须玩家明确继续。

## 未覆盖与保留边界

050 D1批准的活动已逐项注册，仍不支持敌占区自主杀敌、未知人物／宝藏搜索、自动配种／宰杀、营地升阶或拆迁、两营地运输及无限补货。048 D5“只产肉”的旧限制由Owner明确许可的050普通产物规则局部覆盖，自动宰杀禁令继续有效。当前配方没有使用稀有材料的伙伴消耗路径，D4药品授权未外推为未来配方授权。未注册能力不能由模型或手动卡执行。

[26项验收契约](CASES.md)中已有六向容器转移、产物、独立营地外安全采集、同行护送／狩猎／钓鱼／捕获、限定批次生产与回档的定向证据。C01—C26的所有边界组合尚未逐项跑满；尤其自然地图任意远点与动态敌情、真实旧schema8文件迁移、真实本机模型输出、长程角色体验和Shipping为NOT_RUN。原生UE日志中`Condition failed`来自负例断言，自动化报告失败数为0。Owner需要在050工作树而非原main检出目录打开`Hearthward.uproject`验收。
