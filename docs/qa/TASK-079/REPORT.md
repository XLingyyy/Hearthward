## 问题与实现

检查确认 `CaptureContextSnapshot` 读取了目标量和交付量，但投影未使用；确认任务后 `Memory.WorkingGoal` 被清空，模型无法可靠获取执行中的任务。原生回归测试在修改前两项均失败：三档上下文缺少任务对象，查询／续接能力未注册。

- 所有上下文档位保留当前任务类型、物品、来源、阶段、目标、交付、携带、剩余量和阻塞原因。
- 新增只读 `task_status`。模型判断询问意图，UE根据回复时的真实任务生成答复，避免使用过期推理数字。
- 新增 `resume` 待确认卡，绑定原任务ID；确认时复用 `ResumeBlocked` 检查资源、安全和原执行状态。继续原任务，不重新创建32份采集，不抹掉14份已交付进度。
- 已完成／已取消／正在执行的任务不能作为受阻任务重复启动。过期请求、任务更换、存档时间线和世界暂停沿用现有校验。

未增加多任务队列、自动换资源点、自然语言调度族人或新模型。保留单次本地模型推理、注册能力、UE复核、玩家确认的现有结构。设计参考 [Building effective agents](https://www.anthropic.com/research/building-effective-agents) 的简单工具工作流和 [Writing effective tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents) 的明确工具语义与执行验证。
