# TASK-048 首次失败与修复

以下为实际开发期结果，早期PASS不替代最终冻结源码验证。

- 原设计验算按固定ID选源，与046余量最少优先规则不一致。修正纸面模型，未改游戏迁就模型；保留calculation-first-failure.json。
- 初次Editor构建发现头文件顺序、TObjectPtr推导和FRandRange整数重载问题；修正后构建通过。早期头文件修改与编译重叠造成PCH快照问题，后续停止交叠编译／编辑。
- PIE初次观察脚本读取未暴露的NaturalTarget属性失败；改用Actor类型观察，不扩展运行权限。
- 打开自然页面默认暂停，直接启动五秒动作被拒绝。UI先关闭面板回HUD，再通过保存的Epoch开始动作。
- 地面射线曾接受家具顶面，导致田地落在高处且角色超距。改为只接受Landscape或显式测试地面标签。
- 动物模型不同原点导致接地偏移；按实际网格包围盒设置根高度。牵引动物与玩家碰撞导致无法进栏，调整为友方移动不互相阻挡，世界碰撞保留。
- 饲料断言曾要求投喂后库存仍为10，实际两只成年山羊已各支付2份完整窗口；将期望改为6，并断言两只动物的付费窗口，未改变已批准饲料规则。
- 直接浏览自然地图使用独立浏览GameMode，测试找不到产品HUD。观察脚本在内存中设置与正式标题页OpenLevel相同的GameMode，未保存地图。
- 初始精矿一处没有有效地形命中。按稳定点键重试，并在同一批准距离环搜索有效落点，正式地图恢复两处精矿。
- 自然地图实际按E获得草药而非落枝木材。诊断确认旧采集识别器给新的自然Actor灌木外形添加了第二入口；排除已由自然系统管理的Actor。复验同一对象仅一个交互入口、木材增加并反馈“操作完成”。
- 代码检查发现家畜进入营地会触发旧敌人判定；营地安全改为仅计入正在威胁角色的野生动物，人类敌人继续沿用既有逻辑。PIE增加家畜繁殖后营地区域仍安全的断言。
- 自然地图观察截图曾把玩家按动物高度平移到更高山坡下方；仅修正观察脚本从上方落地，增加实际落地断言，不将测试传送错误当作普通行走故障。

对应原始结果保留在本目录build-first、pie-first／second、fourth至ninth、natural-first／second／third／diagnose／fixed记录。所有运行使用同一个拥有该编辑器的UEClient停止本单进程。
