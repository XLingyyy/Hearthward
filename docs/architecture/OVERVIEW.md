# 模块边界草案

状态：PROPOSED，等待TASK-002批准。下列是为协作划定职责，不是现有C++类清单。

| 领域 | 写入权威 | 只读／消费方 |
|---|---|---|
| 库存 | 真实物品与重量变更 | UI、营地、伙伴、任务 |
| 角色状态 | 血量、耐力、饱食及倒地状态 | 战斗、UI、救援、保存 |
| 世界时间 | 日历与实玩时间输入 | 生产、成长、刷新；跳时政策仍受R02约束 |
| 伙伴执行 | 当前委托与执行状态 | UI、知识、世界变更适配 |
| 知识与回复 | 角色可知信息、对话与建议 | 不直接写库存和战果 |
| 关卡／任务 | 实体ID、目标与旗帜控制 | UI、保存；R01/R17未定部分不默认实现 |
| 保存 | 聚合各域快照与恢复协调 | 不替各域决定玩法公式 |

不要求上来做六个插件或复杂事件平台。先统一已有引擎设施上的职责与调用边界，
实际类／模块由契约PR确认；不把目录隔离等同于网络隔离。

禁止：UI直接创建“显示用库存”并与实际库存分别扣料；模型直接宣告任务完成；
每个系统自己计算游戏日；不同任务各写一份基础物品结构；读档只恢复背包不恢复伙伴知识。
